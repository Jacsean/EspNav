## 2. 三分钟上手（改完代码怎么验）

```bash
# 1) 改完代码，先跑静态预检（必须 problems: 0）
python Esp32S3/tools/precheck.py main
python mobileApp/android/tools/kotlin_precheck.py mobileApp/android

# 2) 编译（App 侧我方即可完成；固件需 IDF 环境）
cd mobileApp/android && JAVA_HOME=~/.jdks/jbr-17.0.14 ./gradlew --no-daemon :app:assembleDebug

# 3) 真机（用户侧）
cd Esp32S3 && idf.py -p COM3 build flash monitor
```

> **三条铁律**（详见 §3）：
> 1. 先跑预检 → 2. 必须编译一次 → 3. 编译错误写进 [fault_log.md](fault_log.md)

## 3. 代码质量门（**每次改代码后必做**）

来源：`工作清单与状态.md`，2026-09-14 起执行。

### 3.1 固件静态预检

```bash
python Esp32S3/tools/precheck.py main      # 必须 problems: 0
```

检查项（8）：① 缺 include（函数可见性）② 缺 include（类型可见性）③ 缺**系统头**（stdio/string/math/stdlib）
④ 括号平衡 ⑤ 字符串转义损坏 ⑥ `static` 函数未使用 ⑦ **使用先于声明** ⑧ **控制字符**（0x08 等）

> 检查器本身必须用"曾经出错的版本"反证有效：
> `git show <旧提交>:Esp32S3/main/render/render_nav.c > /tmp/x.c && python Esp32S3/tools/precheck.py /tmp`

### 3.2 App 静态预检

```bash
python mobileApp/android/tools/kotlin_precheck.py mobileApp/android   # 必须 problems: 0
```

检查项：① Kotlin 括号/引号平衡 ② `suspend fun` 内裸用 `isActive` ③ XML 合法性
④ layout id ↔ `binding.xxx` 一致性 ⑤ `@string/...` 引用存在性 ⑥ 未使用 import（提示）

⚠️ **预检覆盖不到**：字符串跨行、类型不匹配、运行时初始化顺序 —— **所以必须编译一次**（见 fault_log F13/F15）。

### 3.3 人工 review 清单（预检抓不到的）

- **数组越界**：缓冲尺寸 vs 最大点数（`geo_fatten` 对 16 点输入可输出 ~34 点 → 多边形 ~68 点）
- **长度/边界**：字符串缓冲、数组下标、循环上界
- **类型混用**：`npt_t`（模板平面坐标）vs `gpt_t`（几何点）vs 投影后屏幕点
- **`snprintf` 逐条核对源与目标宽度**（`-Werror=format-truncation` 会直接失败）：
  `grep -rn "snprintf(" Esp32S3/main/` 全量列出后逐条比对；写驱动结构（如 `char ssid[64]` → `wc.sta.ssid[32]`）一律改**显式长度 memcpy**
- 空指针/未初始化、错误分支的资源释放

### 3.4 Android 编译验证

```bash
cd mobileApp/android && JAVA_HOME=~/.jdks/jbr-17.0.14 ./gradlew --no-daemon :app:assembleDebug
```

必须 `BUILD SUCCESSFUL` 且产出 `app/build/outputs/apk/debug/app-debug.apk`，**再交付用户**。

### 3.5 编译错误必须归档

任何编译失败（含"预检没抓到"的）都要追加到 [fault_log.md](fault_log.md)：现象 / 原因 / 解决方案 / 预防措施。

## 4. 固件开发

### 4.1 常用命令

| 用途 | 命令 |
| :--- | :--- |
| 编译 | `idf.py build` |
| 烧录 + 监视 | `idf.py -p COM3 flash monitor` |
| 只看日志 | `idf.py -p COM3 monitor` |
| 退出监视 | `Ctrl + ]` |
| 清理重编 | `idf.py fullclean && idf.py build` |

### 4.2 模块结构（改功能先定位到文件）

| 改什么 | 去哪 |
| :--- | :--- |
| 屏幕画什么、怎么画 | `render/render_nav.c`（主渲染）、`render/lcd_fb.c`（原语：线/矩形/多边形/虚线） |
| 模板路几何、透视投影 | `render/geo.c`（`geo_fatten` / `geo_proj_pt` / `geo_scale_at`） |
| 报文解析、消息分派 | `protocol/frame_parser.c`（按 `\n` 切帧）、`protocol/protocol.c`（`msg_type` 分派） |
| 帧字段 → 结构体 | `protocol/nav_frame.c` + `nav_frame.h` |
| 配置项（亮度/动画/弹窗超时） | `protocol/config.c` |
| WiFi/配网/TCP | `comm/wifi_sta.c` / `softap_prov.c` / `tcp_server.c` |
| 字库与文字绘制 | `font/font.c`（字库在 `font_data.c`，全 GB2312） |
| 启动顺序 | `app_main.c`（AP → STA → 配网 → mDNS → TCP） |

### 4.3 线程模型（**务必遵守**）

- **只有 `display_task` 能碰 SPI 与帧缓冲**（33ms tick）
- 其它任务（TCP 客户端任务）只做"解析 + 回包 + 置标志"
- 需要清屏？调 `render_nav_clear()` **置请求标志**，实际清屏在 `render_nav_tick()` 里执行
- 违反这条会出现撕裂/花屏 —— 详见 fault_log **F5**（`tcp_srv` 栈溢出）

### 4.4 调试手法

| 场景 | 手法 |
| :--- | :--- |
| 看数据到没到 | `ESP_LOGI(TAG, "RX len=%d type=%s", ...)`（`protocol.c` 里已有入口探针） |
| 看某个数组的值 | 临时探针打印首末坐标（**用完删掉** —— 用户明确不喜欢靠日志排查） |
| 判断"哪条线是谁画的" | 给各绘制来源不同颜色（`DBG_*` 宏）+ App 里的「ESP 显示元素」开关逐个关 |
| 屏幕不刷新 | 先看 App 日志区；固件超过 5 秒没收到帧会**自动回到等待画面**（`LINK_TIMEOUT_US`） |

## 5. App 开发

### 5.1 常用命令

| 用途 | 命令 |
| :--- | :--- |
| 编译 debug APK | `cd mobileApp/android && JAVA_HOME=~/.jdks/jbr-17.0.14 ./gradlew --no-daemon :app:assembleDebug` |
| 装到手机 | `adb install -r app/build/outputs/apk/debug/app-debug.apk` |
| 看 logcat | `adb logcat -s AmapNavSource NavStateMapper EspNavClient MainActivity` |
| 抓崩溃 | App 内 `filesDir/crash.log`（启动时若有会提示） |

### 5.2 包结构

| 包 | 放什么 |
| :--- | :--- |
| `com.espnav.app` | `MainActivity`（连接/导航/行程预览三页 + 设置）、`NavService`（熄屏保活） |
| `.protocol` | `Protocol.kt`：`NavFrame` / `RoadSpec` / `OutMsg` / `InMsg`，JSON 组装 |
| `.net` | `EspNavClient`：TCP 连接、顺序发送、心跳、断线回调 |
| `.data` | `NavSource`（抽象）/ `AmapNavSource`（高德）/ `NavState` / `NavStateMapper`（帧组装）/ `PolylineSampler`（行程图采样）/ `AppPrefs` / `ConfigFile` / `MockNavigator` |
| `.ui` | `TripOverviewView`：导航画面的行程图卡片 |
| `assets/` | `sampling_compare.html`：行程预览页（WebView 加载，同时可在电脑浏览器打开） |

### 5.3 加一个新设置项的标准动作（4 处）

1. `data/AppPrefs.kt`：加属性 + `K_*` 常量（若希望进配置文件，**同时加进 `exportToJson` / `importFromJson`**）
2. `res/layout/dialog_settings.xml`：加控件
3. `res/values/strings.xml`：加文案
4. `MainActivity.openSettings()`：读 → 显示；保存时写回

### 5.4 换/加导航数据源

只要实现 `data/NavSource.kt` 接口，产出 `NavState` 即可 —— 协议、渲染、行程图、导航画面**全部复用**。
参见 [进度与路线图 §3 草案 C](进度与路线图.md)（百度接入草案）。

### 5.5 调试：行程图采样效果

不用装到手机上看 —— 直接看 `sampling_compare.html`（App 的「行程预览」页就是它），
或把真实路径 JSON 粘进去。语法自检：`node --check`（先提取 `<script>`）。

## 7. 已知坑速查（**改代码前扫一眼**）

| 编号 | 一句话 | 教训 |
| :--- | :--- | :--- |
| F1 | 屏幕黑屏 | LCD **CS 必须交给 SPI 驱动逐笔控制** |
| F5 | `tcp_srv` 栈溢出崩溃 | 任务职责单一：**通信任务不绘图** |
| F9/F10 | 缺 include / 使用先于声明 | 先跑 `precheck.py`；**模块级 static 变量集中放文件顶部** |
| F11 | `snprintf` 截断被 `-Werror` 拦下 | 逐条核对源/目标宽度，改显式 memcpy |
| **F12** | **源码写入损坏（复发 5 次）** | **别用 shell heredoc 写源码**；落盘必跑预检 |
| F13 | App 启动闪退 | `onCreate` 里刷新调用必须放在依赖字段初始化**之后**；交付前**真机启动一次** |
| F14 | 改了函数契约漏改调用点 | 改返回语义后 **grep 全部调用点**；用**具名常量**不用魔法数字 |
| **F15** | Kotlin 字符串跨行（补丁脚本 `\n` 写成真换行） | 用脚本生成源码时，要产出 `\n` 必须写 `\\n`；**预检过了也要编译一次** |

完整记录（含解决方案）见 [fault_log.md](fault_log.md)。

## 8. 写代码时的约定

1. **注释写"为什么"，不写"是什么"** —— 尤其是那些看起来奇怪但有意为之的（例如"为什么不直接用 `road_fill`"）
2. **删掉代码要留恢复路径**：用 `if (0)` / 注释块 + 一行说明（本项目已有先例：`past_center` 绘制、车头中轴线）
3. **调试开关优先于临时探针**：能做成 App 开关的（`AppPrefs.dbg*`）就别加固件日志
4. **改协议**：先改 `ble_protocol.md` 并加修订条目，再改两端代码
5. **中文注释**：本项目注释用中文，术语保留英文
