### 草案 A：通知监听（NotificationListenerService）

**目标**：微信 / 短信到通知栏 → 组装 `POPUP_MSG` → ESP 弹窗。

**组件**

| 件 | 说明 |
| :--- | :--- |
| `service/NotifListener.kt` | 继承 `NotificationListenerService`；`onNotificationPosted(sbn)` 里取 `sbn.packageName` + `notification.extras` |
| `res/xml/notif_listener.xml` | `<notificationlistener android:label="EspNav 通知转发" />` |
| Manifest 声明 | `<service android:name=".service.NotifListener" android:permission="android.permission.BIND_NOTIFICATION_LISTENER_SERVICE"><intent-filter><action android:name="android.service.notification.NotificationListenerService"/></intent-filter><meta-data .../></service>` |
| 权限引导 | 设置页加按钮：跳 `Settings.ACTION_NOTIFICATION_LISTENER_SETTINGS`；用 `NotificationManagerCompat.getEnabledListenerPackages()` 判断是否已授权 |

**过滤规则（建议初值）**

| 项 | 规则 |
| :--- | :--- |
| 包名白名单 | 微信 `com.tencent.mm`；短信：`com.android.mms` / `com.google.android.apps.messaging` / `com.huawei.mms`（按实测机型补） |
| 取字段 | `Notification.EXTRA_TITLE`（标题）→ `title`；`Notification.EXTRA_TEXT`（正文）→ `content` |
| 去重 | `(pkg + title)` 在 **5s** 窗口内只发一次（对齐 `实施方案.md:70` 的 L3 决策） |
| 过滤噪声 | 忽略 `EXTRA_GROUP_SUMMARY`（微信"2 条新消息"汇总）、忽略前台服务/正在进行的通知（`FLAG_ONGOING_EVENT`） |

**下发**：`POPUP_MSG { title, content, timeout }`，`timeout` 取固件侧 `popup_timeout`（不传则由设备默认）。

**降级（可选）**：用户显式开启 `READ_SMS` 时，对短信额外走 `ContentObserver`；**始终以通知为准**，两者都用 sender+5s 去重。

**边界（务必写进用户手册）**：只能读通知栏快照；微信若在"通知改为不显示内容"或锁屏隐藏内容，则拿不到正文。

**第一步**：先做 `service/NotifListener.kt` + Manifest + 设置页授权引导；先只支持短信，验证通路后再加微信。

### 草案 B：航向传感器模块

**现状问题**：`heading` 取自高德 `bearing` —— 静止时不更新、低速时抖动；且换 SDK（百度）就得重新对。

**方案：`Sensor.TYPE_ROTATION_VECTOR`**（融合了加速度计+陀螺+磁力计，比 `TYPE_ORIENTATION` 更稳）

```
SensorManager.getRotationMatrixFromVector(R, event.values)
SensorManager.getOrientation(R, orientation)
azimuth = Math.toDegrees(orientation[0])   // 弧度 → 度，0=北，顺时针
```

**低通滤波（一阶 IIR）**，α 随速度自适应：

| 状态 | α | 效果 |
| :--- | :--- | :--- |
| 静止（speed < 1 m/s） | 0.05 | 重滤波，压掉抖动 |
| 低速（1–3 m/s） | 0.12 | 折中 |
| 骑行（> 3 m/s） | 0.25 | 跟手 |

```
y[n] = α · x[n] + (1 - α) · y[n-1]
```

**角度环绕**：算差值必须 `((a - b + 540) % 360) - 180`，否则 359°→1° 会显示成"转了一大圈"。

**与高德 bearing 的取舍（建议）**

```kotlin
if (speedMps > 1.5 && bearingValid) 用高德 bearing    // 行进中：bearing 与路线方向一致，最可靠
else                                用传感器 azimuth  // 静止/启动瞬间：传感器的绝对方位可用
```

**落地位置**：新增 `sensor/HeadingProvider.kt`，在 `NavStateMapper.toFrame()` 组装 `heading` 处取它的值；
`AmapNavSource` 继续提供 `speedKmh`（用于选 α 与上面的取舍）。

**第一步**：把 `HeadingProvider` 写出来（只需 `Context` + `SensorManager`），先在 App 里打日志对照高德 bearing，确认偏差可接受再替换。
