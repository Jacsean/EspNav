# 交付前 Review 清单（每次写完代码必做）

> **用户强制要求（2026-10-10）**：每次写完代码，都要 review 一下 ——
> ① **是否真的完成？** ② **迭代内容对已有功能有没有负面影响？** ③ **是否会让曾经解决过的问题再次出现？**
> **这三条对我所有任务都执行，不区分任务大小。**

## 一、三项必答（要证据，不能凭感觉）

| # | 问题 | 怎么答 |
| :--- | :--- | :--- |
| ① | **真的完成了吗？** | 逐条列「改了什么 → 对应哪个验收点」；**能自动验的必须自动验**（编译过 / 预检 0 问题 / 静态核对 / 产物时间戳） |
| ② | **对已有功能有负面影响吗？** | 列出本次改动**触碰的共享资源**（任务、缓冲、GPIO、协议字段、NVS、布局 id、文件），逐一说明"还有谁会用到它、是否受影响" |
| ③ | **会让旧问题复现吗？** | 打开 `fault_log.md`，逐条核对 **F1..Fn**：本次改动是否重新引入了同类条件（如又一次"静默失败""无界增长""abort 整机"） |

## 二、实操检查（按改动类型选做）

| 改动类型 | 必做 |
| :--- | :--- |
| **固件：新增模块** | ① 初始化**失败不得 `abort` 整机**（新模块禁用 `ESP_ERROR_CHECK` 包裹）② 初始化顺序放在**显示/联网之后**，或放**独立任务** ③ 用 `Esp32S3\tools\build_fw.ps1` **真编译** |
| **固件：改共享资源** | `rg` 全仓确认引用点；确认线程约定（谁写谁读、是否跨任务、有无竞态） |
| **固件：改协议** | 三方一致（App / 固件 / 协议文档）；**向后兼容**（旧 App 不发新字段时不能崩） |
| **APK：改布局** | 控件 **id 不变**；跑 `kotlin_precheck.py`；`findViewById<T>` 的 **T 与 XML 控件类型兼容**（F18 教训） |
| **APK：改绑定** | **ViewBinding 与 findViewById 两种形式都要核**（F21 教训：只扫一种会误判） |
| **任何提交** | **真编译产物**（固件 `build_fw.ps1` / APK `gradlew assembleDebug`）—— **只跑预检不算过**（F17 教训） |
