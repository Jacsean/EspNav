# 交付与更新记录（每次要更新什么）

> **为什么有这份表**：此前交付时常只写"去做某某验证"，却没明确"要更新固件还是 APK"，导致无谓来回。
> **读法**：
> - **固件 ✅ 必烧** = 必须重编并烧录固件（`build_all.cmd` → `flash.cmd`）
> - **APK ✅ 必装** = 必须重编并安装 APK（`build_all.cmd` → `install_apk.cmd` 或拷 `out\espnav-debug.apk`）
> - **—** = 该侧本次无改动，可不更新
>
> **一句话规则**：两侧有一侧没更新，新功能就不完整（App 不发数据 / 固件不认新报文）。

## 一次性准备（只需做一次）

| 项 | 说明 |
| :--- | :--- |
| 双击 `build_all.cmd` | 建立 `out\`（含 `espnav.bin` / `bootloader.bin` / `partition-table.bin` / `espnav-debug.apk`） |
| 串口 | 默认 `COM3`；不对就 `flash.cmd COM5` |
| 占用 | 烧录前关掉其它串口监视器窗口（否则 `Could not open COM3`） |
| 配置文件 | 排查期间建议把 `/sdcard/Download/EspNav/espnav_config.json` 改名或每次启动点「不覆盖」，避免设置被旧值覆盖 |

## 手工烧录命令（不想双击脚本时）

```powershell
cd D:\example\projects\Esp32Nav\v1.0.0.1\out
& "C:\Users\jwgbo\.espressif\python_env\idf6.1_py3.10_env\Scripts\python.exe" -m esptool --chip esp32s3 -p COM3 -b 460800 --before=default-reset --after=hard-reset write-flash --flash-mode dio --flash-freq 80m --flash-size 16MB 0x10000 espnav.bin
```

仅烧 app 即可（bootloader/分区表未变）；换分区表或刷空白板时才用完整三件套（见 `out\` 内文件）。
