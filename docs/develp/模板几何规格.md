# 模板几何规格（草案 V0.1）— H1-A 参数化几何层

> - 状态：**草案待评审**（2026-09-03）。本文件是审查决策 H1-A 的产物，评审通过后才进入 v2 参数化改造与 ESP32 C 版移植。
> - 关联文档：`ble_protocol.md` V1.7 §3.1.1（字段与 type×dir 组合表）；`技术实现路径.md` §1.5/§1.6（投影常量、切换时序）。
> - 视觉验收基准：`nav_sim_v2.html`（主视图集成、近大远小）与 `nav_sim_v3.html`（平面整屏样例）。

## 0. 目的与范围

打通三段参数化链路，替代当前"写死坐标 CASE"（v2 `ROAD_CASES` / v3 `CASES`）：

```
手机端（生成器）            帧 road 字段              渲染端（解释器）
导航真实走向 ──► type/dir/exits/pts/cx/cy/r/half ──► 路网+绿路径+车标
                                                    （HTML V2 参数化版 = C 版 1:1 基准）
```

- **手机端生成器**：由导航 SDK 机动与路线走向，产出协议字段（见 §6）。
- **渲染端解释器**：只读字段参数化生成画面，不解释业务语义（见 §5）。

## 1. 坐标系与公共常量（两端地基）

1. 平面坐标：**车头朝上**屏幕像素系，x: 0~319（右为正），y: 0~239（下为正）；车辆自**底部南入口**进入画面；N=上、E=右、W=左、S=下。
2. 投影（V2 冻结）：`PROJ={cx:160, yNear:130, yFar:20, sNear:1.0, sFar:0.24}`，深度 y 线性缩放；主视图绘制前另施"底部生长"缩放（锚 y=22、k=1.1）。常量以 `nav_sim_v2.html` `PROJ`/`drawScene` 为准（技术路径 §1.5 已同步）。
3. 半宽体系（决策 M2-A，保留两套、文档化口径）：
   - 行驶条带：近宽 150px→远 36px，由发送端 `centerLine` 首末点直接决定；
   - 模板体系：基准半宽 `road.half`（缺省 62px，近端视觉宽≈124px·k≈136），支路半宽按 §5.4 系数缩放；
   - 两体系**同轴不同宽**，衔接处（y≈130-134）的宽度不连续由手机端 centerLine 近端坐标与模板南引路协同对齐（技术路径 §1.6 帧序 2 口径）。

## 2. 帧字段 → 几何参数映射（V1.7）

| 字段 | 用途 | 缺省 |
| --- | --- | --- |
| `type` | 模板类别（7 类） | 无（缺省=行驶条带） |
| `dir` | 车头相对机动方向 `straight/left/right/exitN` | straight |
| `exits` | （roundabout）出口方位数组，**不含入口**，按行驶方向排序 | 缺省 `['E','N','W']` |
| `pts` | 导航真实走向平面折线（≤16 点），含环岛内离散弧 | 无（缺省=主路直线） |
| `cx/cy/r` | roundabout 平面圆心与半径 | 160 / 84 / 52（平面值，见 §5.5） |
| `half` | 路面基准半宽（平面 px） | 62 |
| `maneuver` | 顶部提示/符号与机动口径 | 无 |

> 约束：`pts` 首点应位于南入口引路近端（y≈134 平面带），末点位于出口方向；`pts` 点数 ≤16 与 `centerLine` 同限。

## 3. type×dir×exits 语义（H2-A）

### 3.1 合法组合（与 ble_protocol V1.7 §3.1.1 一致）

| `type` | 合法 `dir` | 几何要点 |
| --- | --- | --- |
| `straight` | （缺省） | 直路，条带体系即可；一般不需模板 |
| `curve` | `left / right` | 单弯，路径 pts 为弯折线 |
| `tjunc` | `left / right` | T 口，支路在左/右，必转向 |
| `cross` | `straight / left / right` | 十字四向 |
| `multi` | （缺省） | 多岔，支路方向由 pts 尾段推断 |
| `roundabout` | `exitN` | 目标出口 = `exits[N-1]`（见 3.2） |
| `fork` | `left / right` | 主路直行 + 单侧匝道驶出 |

### 3.2 roundabout 的 `exitN` 与 `exits` 计数约定（关键裁决）

- `exits` **不含南入口**，按车辆绕行方向排列：`exits[0]` = 入口后第 1 个可驶出口。
- `dir=exitN` / `maneuver=roundabout_N` 的 **N 按导航 SDK 播报口径**（入口后第 N 个出口，沿真实绕行方向），由**手机端**解释后映射到 `exits` 下标（目标 = `exits[N-1]`）再下发。
- **渲染端不解释 N 的绕行方向**：绿路径一律取"南入口 → 沿椭圆环带按最近角度差到达目标出口方位"（即 v3/v2 现有短弧走法）；绕行方向差异只影响手机端对 exits 的排序。
- ⚠️ 与 v3 样例标注（"4 出口第2出口=东"）的计数口径可能不一致，**列为开放问题 O1**，以导航 SDK 实测校准（实施计划风险 5）。

### 3.3 uturn

- `maneuver=uturn`：建议**不带 `road`**——行驶条带 + 顶部"掉头"符号 + `routeCenter` 内 U 形弧折线（手机端生成弧线点）；不套任何路口模板。
- 若确需放大造型，允许 `road.type=curve` + U 形 `pts`（几何仍按弯道画，[TODO] 专用造型待定）。

## 4. `pts` 语义与绿路径

1. `pts` = 该路况段内**导航真实走向**的平面折线（含路口内转向、环岛内离散弧），与路网分离：路网是背景示意，`pts` 为准（协议叠加规则）。
2. 渲染端：`pts` 经 `proj` 透视后，暗绿打底 + 亮绿描边绘制（同 `navPath`），始终最上层；车辆光标位置：
   - 帧含 `pos` 且在模板段内 → 车标 = `pos`（手机端在转向过程中沿 pts 推进 pos，对应技术路径 §1.6 帧序 3）；
   - `pos` 缺省 → 南入口引路起点（≈ v2 冻结 `TP_CAR` 语义：较 pts 起点上移约一个车身，路径尾段在车后可见）。
3. `centerLine` 在模板段内可继续发送，渲染端忽略条带绘制（避免双层路面），切回行驶条带时恢复使用。

## 5. 渲染端生成器规则（草案：按 type 产出画面）

统一管线：`readRoad(f)` → 计算路网支路中心线集合 → 各支路 `fatten`+边线（导航道路流动虚线/非导航静态，V1.6 冻结）→ 路口面片 → 叠加绿路径（帧 `pts`）→ 车标。

### 5.1 通用几何量

- 南入口引路：`[[160, 134+], C]`，半宽 = `half`，**流动**（必经，当前路延续）。
- 路口中心 `C`：由 `pts` 首个显著折点求取；`pts` 无折（straight/curve 缓弯）时不生成路口面片、仅沿 pts 画路。
- 支路出口：到屏幕边（或视野上缘 y≈22）截断。

### 5.2 各 type 草案

| type | 路网（支路） | 选中路径 |
| --- | --- | --- |
| `tjunc(dir)` | 南引路 + 单侧支路（dir=left 向左、right 向右），半宽 side | 南引路→C→支路（流动） |
| `cross(dir)` | 四向支路；未选中支路静态、选中方向流动（V1.6：仅导航道路流动虚线） | 南引路→C→dir 方向 |
| `multi` | 南引路 + `pts` 离开 C 的每段各画一条静态支路（去重后 ≤5），选中段流动 | 南引路→C→选中 pts 尾段 |
| `fork(dir)` | 主路直行（静态边线 + 车道中线，非导航）+ 分叉匝道（半宽 side-δ，沿 dir 侧） | 匝道 pts |
| `curve(dir)` | 仅沿 pts 画路（roadStraight 类，半宽 half） | pts |
| `straight` | 同 curve | pts |

### 5.3 roundabout（帧参数驱动）

- 路面：平面圆心 `(cx,cy)`、外径 `r`；透视后呈横椭圆。**冻结观感换算公式（草案）**：环带外半轴 `a=r+δa、b=(a)/1.7`，内岛 `aIn≈a·0.655、bIn≈b·0.435`——先以 v2 `rbtCase` 冻结参数（a58/b23、aIn38/bIn10，rOut 平面 52）反推系数；**列为开放问题 O2**（需在 v2 参数化时以快照逐模板对表定稿，不先行写死）。
- 支路：按 `exits` 各方位画静态支路（长度到边，半宽 side）；目标出口支路流动。
- 绿路径：南引路 → 沿环带中线（`(a+aIn)/2、(b+bIn)/2` 椭圆参数角）从 θ=90°（南）按**最近角度差**至目标方位 → 驶出支路（同 v2 `ellArcPts`，离散 16 段与 C 一致）。

### 5.4 半宽系数（草案，O5 待定稿）

| 量 | 值（相对 `half`） | @half=62 |
| --- | --- | --- |
| 主通行半宽 | `half` | 62 |
| 支路 side | `0.56·half`（= v2 TPL.side 35） | 35 |
| 匝道/环岛支路 ring | `0.44·half` | 27 |
| 匝道本身（fork 路面） | `side-6`（v2 冻结） | 29 |

### 5.5 roundabout 平面缺省值

`cx=160, cy=84, r=52`（平面；v2 `rbtCase` 使用 cy=84 系投影前平面近似，O2 一并精化）。

## 6. 手机端生成器职责（阶段 4-1 输入）

1. 输入：SDK 机动事件（类型/环岛出口 N/提示文本）、`turn_dist`、路线 polyline（车前段）。
2. 输出：`type/dir/exits/pts/cx/cy/r/half/maneuver`（映射规则见 §2/§3），以及模板段内逐帧推进的 `pos`。
3. 校验：type×dir 合法（§3.1）；`pts` ≤16 点且界内；`exits` 排序符合绕行方向（§3.2）；非法组合退回"不带 road 的条带帧"（协议兜底）。
4. 时序：沿用技术路径 §1.6（≤200m 进入、150-250ms 淡入、驶出 ≥60m 退出、heading 限速旋转——pts 以进入时刻 heading 为基准生成，段内不随 heading 重投影）。
5. 一致：生成器产出的字段需能通过 HTML V2 参数化版逐帧复现（自动化对照），再进入 C 版。

## 7. v2 参数化改造清单（评审通过后执行，黄区）

1. 新增 `readRoad(f)`：读 `road` 字段 → §5 管线；`ROAD_CASES` 写死坐标函数退役（保留为回归基线若干轮）。
2. 样例/按钮层改为构造 `road` JSON 驱动（v3 各 CASE 平移到 road JSON 样例集，并入主仿真，消除 v2/v3 样例分裂）。
3. 新增"帧↔画面"对照测试：同一 road JSON，旧写死渲染 vs 参数化渲染快照比对（允许以参数化版为准更新基线一次）。
4. 投影/椭圆常量集中为可配置常量块（`PROJ`/`TPL`/环岛系数），供 C 版对照移植。

## 8. 开放问题（评审点）

- **O1**：`exitN` 计数口径 vs v3 样例标注 vs 导航 SDK 播报（需实车/模拟数据校准）。
- **O2**：roundabout 帧参数（`cx/cy/r`）→ 冻结观感（椭圆轴/内岛）的换算公式定稿。
- **O3**：`multi` 支路上限与方向推断规则（pts 尾段聚类）。
- **O4**：uturn 专用造型是否进入模板库（V1.7 暂以条带+U 弧 pts 表达）。
- **O5**：半宽系数表（§5.4）逐类定稿。
- **O6**：模板态车标定位（帧 `pos` vs 缺省起点）与 v2 `TP_CAR` 语义对齐。
- **O7**：hint/maneuver 顶部符号与 9 全角容量的映射表（符号字形）。
