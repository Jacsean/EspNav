# 实施方案
## 1.项目概述
本项目实现手机导航信息外置显示；手机运行高德/百度导航，将导航提示、距离、航向、行程统计，以及手机短信、微信通知，通过BLE蓝牙下发至ESP32‑S3；在2.8寸320×240 SPI‑LCD上显示。
> 设计约束：不获取真实道路矢量轮廓；**道路统一采用宽条带模拟绘制**，不还原真实路口几何形状。

## 2.系统总体组成
系统分为三大部分：手机端APP、BLE蓝牙通信链路、ESP32‑S3显示终端。

### 2.1 手机端APP
- 对接高德/百度导航SDK，接收导航实时回调事件。
- 获取手机传感器航向角。
- 监听系统通知，支持短信、微信消息抓取。
- 将业务数据封装为 JSON 报文（见 ble_protocol.md），通过 BLE 发送给ESP32‑S3。
- 提供简单控制UI：连接设备、切换导航源、开关消息转发。

### 2.2 通信链路（BLE蓝牙，优先方案）
- ESP32‑S3作为BLE Server；手机APP作为BLE Client。
- 自定义 GATT 服务与特征值（FFB0/FFB1/FFB2）；传输 JSON 报文（见 ble_protocol.md）；
- 导航数据刷新率：5‑10fps；消息事件为事件触发推送。

### 2.3 ESP32‑S3终端硬件
硬件清单：
| 器件               | 说明                                                         |
| ------------------ | ------------------------------------------------------------ |
| ESP32‑S3 主控     | DevKitC‑1（N8R2：8MB flash + 2MB PSRAM）；BLE、SPI 外设；ESP‑IDF v5.1+ / NimBLE |
| 2.8寸 SPI LCD 模块 | 分辨率 320×240、RGB565、黑底；驱动 IC 默认 **ILI9341**（lcd_driver 做 IC 抽象层，同类 SPI LCD 可切换） |
| 供电               | 5V USB 供电（开发）；车载 USB（实车阶段5 验证）              |

ESP32‑S3终端软件能力：
1. BLE 接收 JSON 报文，按 `\n` 重组并解析；
2. LCD底层绘图原语：填充矩形、画线、虚线、多边形、文字绘制；
3. **导航渲染模式：透视梯形模拟道路**（近宽远窄、流动边界虚线，渲染基准以 HTML 模拟器为准），不还原真实路口；
4. 导航UI：提示文本、转向距离、航向罗盘、行程统计、缩略路线；
5. 消息弹窗渲染：收到微信/短信时弹出消息内容；
6. 报文合法性校验：非法 JSON 丢弃并计数，经 DEV_STATUS `err` 上报。

### 2.4 目标硬件与环境规格
**手机端（目标平台）**
- 设备：华为 Mate 40 Pro；系统：HarmonyOS 4（含 AOSP 兼容层，运行 Android APK）。
- 平台边界：本方案基于 Android 应用模型在鸿蒙 4 兼容层运行，**不承诺 HarmonyOS NEXT（纯血鸿蒙）**；如迁移 NEXT，需重新评估高德/百度鸿蒙 SDK 与通知监听 API（开发量另行评估）。
- 导航源：高德 AMapNavi + 百度 BaiduNavi（Android SDK）双接入，经 NavSource 抽象切换；两 SDK 在鸿蒙 4 兼容层的运行兼容性列为阶段4 实测项。
- 消息源：微信 + 短信，经 NotificationListenerService 抓取通知栏快照（内容可达性与降级策略见系统边界）。
- 鸿蒙 4 特有设置引导（交付文档需含）：
  1. 通知监听：设置 → 通知 → 更多通知设置 → 通知使用权 → 开启本应用；
  2. 后台保活：设置 → 应用 → 应用启动管理 → 本应用关闭自动管理，允许自启动/被关联启动/后台活动；同时加入电池优化白名单；
  3. 导航期间保持前台运行（通知栏常驻通知，防止被系统回收）。
**ESP32‑S3 终端（板级规格）**
- 主控：ESP32‑S3‑DevKitC‑1（N8R2：8MB flash + 2MB PSRAM；flash 满足 16×16 点阵字库 ≈230KB + 固件存储）。
- LCD：2.8 英寸 SPI，320×240，RGB565，黑底；驱动 IC 默认 **ILI9341**，lcd_driver 做 IC 抽象层。
- 接线：SPI（SCLK/MOSI）+ DC/CS/RST + 背光 PWM；引脚表待实物到货后定稿。
- 工具链：ESP‑IDF v5.1+，BLE 协议栈 NimBLE，编译烧录 `idf.py`。
- 帧缓冲：LCD 控制器自带 GRAM；显示任务 30fps 重绘如需平滑，可用单帧缓冲（320×240×2B ≈150KB，SRAM 足够）。

## 3.系统功能列表
### 3.1 导航核心功能
1. 导航提示文本显示：如“前方300米向右前方行驶”
2. 转向剩余距离显示
3. 航向罗盘指示（手机传感器heading）
4. 行程统计：总里程、已完成百分比、耗时、预计到达时间ETA
5. 路线缩略图（overview，由导航polyline经纬度转换而来）
6. 模拟道路绘制：统一宽条带道路，不做真实路口几何
7. 当前位置标记（三角光标）

### 3.2 消息扩展功能
1. 短信消息转发显示：发送人+短信内容
2. 微信通知转发显示：发送人+消息摘要
3. 消息弹窗显示，支持超时自动消失

### 3.3 辅助功能
1. BLE连接状态显示
2. 通信错误提示
3. APP端：BLE设备扫描连接、切换高德/百度导航源、消息转发开关

## 4.非功能需求
1. LCD分辨率固定320×240；
2. BLE导航刷新率5‑10fps；消息为事件驱动推送；
3. ESP32‑S3不做地图计算，仅做渲染；所有业务计算全部放在手机端；
4. 不使用OV2640摄像头；
5. 放弃真实路口几何还原，统一宽条带模拟道路。

## 5.系统边界
1. 不修改高德/百度原始导航APP；需要使用本项目自研Android APP集成导航SDK；
2. 微信消息读取依赖安卓通知监听权限，**不能读取微信内部数据库，仅读取系统通知栏消息快照**；
3. 不支持iOS，仅支持Android / 鸿蒙OS。
