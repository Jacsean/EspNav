# 架构与数据流

> 想搞懂"数据从高德回调一路怎么变成屏幕上的像素"就看这份。
> 改代码的实操见 [开发指南](开发指南.md)；还剩什么没做见 [进度与路线图](进度与路线图.md)。

---

## 1. 系统三层

```
┌──────────────────────────── 手机 App（Android）────────────────────────────┐
│  AmapNavSource（高德骑行导航）                                              │
│      ├─ onCalculateRouteSuccess → 全量路径 pathAllCoords                    │
│      ├─ onNaviInfoUpdate        → turnType / 距离 / 路名 / 速度 / ETA       │
│      └─ onLocationChange        → 当前位置 + bearing                        │
│                        ↓ 统一成 NavState                                    │
│  NavStateMapper.toFrame() → NavFrame（协议帧）                              │
│  EspNavClient → TCP :8899（JSON 一行，按 \n 分帧）                          │
└────────────────────────────────────────────────────────────────────────────┘
                                    ↓ WiFi-TCP
┌────────────────────────── ESP32-S3 固件（ESP-IDF）─────────────────────────┐
│  tcp_server 收字节 → frame_parser 按 \n 切帧 → protocol_handle 分派          │
│      → nav_frame_on_json_line() 解析进 s_nav 结构体                         │
│      → render_nav_set_frame(&s_nav)                                        │
│  display_task（33ms tick）→ render_nav_tick() → draw_frame()               │
│      → lcd_fb 帧缓冲 → SPI 40MHz → ILI9341 320×240                          │
└────────────────────────────────────────────────────────────────────────────┘
```

**唯一的契约是协议**（[ble_protocol.md](ble_protocol.md)）：
换导航 SDK（高德→百度）、换手机、甚至换渲染端，只要还会说这个协议，另一端就不用动。

## 2. 模块职责

### 2.1 固件 `Esp32S3/main/`

| 模块 | 文件 | 职责 |
| :--- | :--- | :--- |
| 启动 | `app_main.c` | 启动序列：softAP → STA → 配网 → mDNS → TCP Server |
| 显示任务 | `display_task.c` | **唯一**访问 SPI/帧缓冲的任务；33ms tick 决定画开机画面还是导航画面 |
| 通信 | `comm/wifi_sta.c` `wifi_ap.c` `softap_prov.c` `tcp_server.c` `mdns_service.c` `ble_fallback.c` | WiFi 多凭据自动重连、配网页、TCP Server、mDNS（待做）、BLE 备用（待做） |
| 协议 | `protocol/frame_parser.c` | 字节流 → 按 `\n` 切成一帧一帧（行缓冲 4096，回调前补 NUL） |
| | `protocol/json_lite.c` | 极简 JSON 取值（不用外部库，见 fault_log F4） |
| | `protocol/protocol.c` | `msg_type` 分派：`HELLO`/`PING`/`GET_CONFIG`/`SET_CONFIG`/`CLEAR_SCREEN`/`NAV_FRAME`/`BYE`… |
| | `protocol/nav_frame.c` + `nav_frame.h` | 帧字段 → `nav_frame_t` 结构体（**点数上限 `NAV_MAX_PTS=16`**） |
| | `protocol/config.c` | 设备配置（亮度/动画/弹窗超时/版本号 `firmware_ver`），NVS 持久化 |
| 渲染 | `render/render_nav.c` | 主渲染：开机画面、主视图、罗盘、行程图、文字层 |
| | `render/geo.c` | 模板几何 + 透视投影（`geo_fatten` 逐点法线加宽、`geo_proj_pt` 透视、`geo_scale_at` 近大远小） |
| | `render/lcd_fb.c` | 帧缓冲与绘图原语（线/矩形/多边形/虚线/三角） |
| 字库 | `font/font.c` + `font_data.c` | 16×16 点阵，**全 GB2312 6763 汉字 + ASCII**；`font_draw_text_scaled` 支持放大 |
| LCD | `lcd/lcd_driver.c` `ili9341.c` | SPI 驱动；**CS 必须逐笔控制**（fault_log F1） |

### 2.2 App `mobileApp/android/app/src/main/java/com/espnav/app/`

| 包 | 文件 | 职责 |
| :--- | :--- | :--- |

## 3. 一次导航的完整数据流

### 3.1 算路阶段（点「预览路线」）

```
地图选点 或 地址文本
   ↓
AmapNavSource.calculateRoute() / geocodeAndRoute()
   ↓（高德回调）
onCalculateRouteSuccess
   ├─ pathAllCoords = coordList            ← 全量路径（数百~数千点）★主视图用
   └─ pathCoords    = PolylineSampler.sampleGeo(pathAllCoords, mode, 16)
                                           ← 采样到 ≤16 点 ★行程图用
```

> **为什么两份数据**：主视图要"车头附近 400 m 的精确形状"，行程图要"整条路线像不像"，
> 需求不同 → 数据不同（这是 v1.1.0 修正的核心问题之一）。

### 3.2 每帧（推流循环 200ms）—— App 侧

```
refreshPathProjection()                       ← 定位/朝向更新时也会调用
  ├─ i0 = nearestIndex(origin)                ← 在全量路径上找离车最近的点
  ├─ aheadRaw  = 沿路径向前 400 m（点连续、顺序正确）
  ├─ behindRaw = 沿路径向后 60 m
  ├─ baseHeading = headingDeg（车头朝向，取自 bearing）
  ├─ remainPath = project(ahead, origin, heading, pxPerMeter = 114/400)
  ├─ overviewProjectorFor(pathCoords) → overviewPath（局部坐标 0..200，北在上）
  └─ overviewDotPos = 投影当前定位                    ← 黄点，不用"按进度取索引"

NavStateMapper.toFrame(state) → NavFrame
  ├─ heading / turnDist / hint / totalDist / progressPct / elapsedMin / etaTime
  ├─ centerLine（remainPath）/ pastCenter / routeCenter
  ├─ pos = (160,110) 固定
  ├─ overview / overviewDot
  └─ road = RoadSpec（由 turnType 决定用哪个模板；ARRIVE/UTURN 也发 STRAIGHT 模板）

applyDbgMask(frame)            ← 设置里的「ESP 显示元素」开关在这里过滤
   ↓
OutMsg.navFrame(frame) → JSON 一行 → EspNavClient.queue() → TCP
```

### 3.3 ESP32 侧

```
tcp_server（client_task）收字节
   ↓
frame_parser：按 \n 切帧 → 行缓冲补 NUL → 回调
   ↓
protocol_handle(line) → 判 msg_type
   ↓ NAV_FRAME
nav_frame_on_json_line() 解析进 s_nav（nav_frame_t）
   ↓
render_nav_set_frame(&s_nav)           ← 只更新结构体，不绘图（线程约定）

display_task 每 33 ms：
   protocol_link_stage() == LINK_STAGE_WAIT_APP ?
        → render_nav_boot()（开机画面）
        → 否则 render_nav_tick(dt) → draw_frame(f)
              ├─ road.present ? draw_road()        ← 7 类模板（geo 投影 + 逐点法线加宽）
              │                : road_fill_screen() ← 用真实路径画路面（fallback）
              ├─ 车头三角（pos）
              ├─ draw_compass()   ← 8 方位 + 车头下方"方位+角度"（亮青）
              ├─ draw_overview()  ← 行程图：轨迹 + 起终点 + 当前位置黄点 + "北"指示
              └─ 文字层：hint / 距离 / 全程 / 耗时 / ETA / 路名 / STA 网络状态
           → fb_flush()（整屏刷到 SPI）
```

## 4. 协议字段 → 屏幕元素

| 协议字段 | 屏幕上的东西 | 备注 |
| :--- | :--- | :--- |
| `heading` | 罗盘方位刻度 + 车头下方"方位+角度"文字 | 主视图的"车头朝上"旋转由 **App** 完成，`heading` 只驱动罗盘 |
| `turn_dist` + `hint` | 顶部提示行（绿色，超长滚动） | `hint` 由 App 组装（"前方 500 米右转"） |
| `total_dist` / `progress_pct` / `elapsed_min` / `eta_time` | 左下行程统计 3 行 | |
| `road` | **透视路面 + 转向图形** | 7 类模板：straight / curve / tjunc / cross / multi / roundabout / fork |
| `centerLine` | fallback 路面 + 车道中线虚线 | `road` 为空时才用（ARRIVE/UTURN 现已发模板，故通常不用） |
| `pastCenter` / `routeCenter` | （已按用户要求删除绘制） | 代码以 `if (0)` 保留 |
| `pos` | 车头三角（黄） | 固定 (160,110) |
| `overview` + `overview_dot` | 右上角行程图 + 当前位置黄点 | 局部坐标 `0..OV_SPAN(200)`，北在上 |
| `roadName` | 罗盘下方滚动路名 | |
| `speed` | （预留） | 目前只在日志里 |
| `notice` | 中部黄色提示行 | 路况/设施提示，App 暂未填充 |

**跨端常量**（**改一侧必须同时改另一侧**）：

| 常量 | App | 固件 |
| :--- | :--- | :--- |
| 帧点数上限 | `PolylineSampler.MAX_N = 16` | `NAV_MAX_PTS 16` |
| 行程图坐标跨度 | `NavStateMapper.OV_SPAN = 200` | `OV_SPAN 200` |
| 行程图区域 | — | `OV_AX 190` / `OV_AW 130` |
| 屏幕几何 | 320×240 / `NEAR_Y=144` / `FAR_Y=30` / `CX=160` | `FB_W/FB_H` / `NAV_NEAR_Y=144` / `NAV_FAR_Y=28` / `NAV_CX=160` |

## 5. 关键设计决策（为什么是这样）

| # | 决策 | 理由 |
| :--- | :--- | :--- |
| 1 | **ESP32 只渲染，不算路** | 手机算力/网络都强；屏幕端换 SDK、换手机都不受影响 |
| 2 | **单帧点数上限 16** | 协议约定（TCP 帧体积 + 固件缓冲）。所以行程图必须"按几何重要性取点"而不是等间隔 |
| 3 | **路面用模板，不用真实路形** | 模板观感稳定、可预期；实测"按真实路径画路面"形状不可控（用户 2026-09 反馈差） |
| 4 | **主视图与行程图用两份数据** | 主视图要车前 400 m 的局部精度；行程图要整条路线的整体形状 |
| 5 | **黄点用"当前定位投影"而非按进度取索引** | 采样后点距不均，按索引会跳变 |
| 6 | **`heading` 只驱动罗盘** | 主视图已是"车头朝上"坐标系，旋转在 App 侧完成 |
| 7 | **调试开关做成 App 端可切** | 排查"屏幕上有条怪线"时不用反复烧固件 |
